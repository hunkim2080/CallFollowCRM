# 네이버 블로그(스마트에디터 ONE) 자동화 노하우

CDP(Chrome DevTools Protocol) + Playwright로 네이버 블로그 PC 글쓰기(스마트에디터 ONE)를
자동화하면서 실제로 알아낸 것들을 정리했습니다. 공식 문서에 없는 "함정"들이 핵심입니다.

> 전제: 자동화용 Chrome을 `--remote-debugging-port=9222`로 띄우고 네이버에 **미리 로그인**해 둔 상태에서
> `playwright-core`의 `chromium.connectOverCDP('http://127.0.0.1:9222')`로 붙습니다. (자동 로그인 시도 금지)

---

## 0. 절대 원칙

- **자동 발행 금지.** 코드에 '발행' 버튼 셀렉터를 두지 말고, 클릭 직전 요소 텍스트에 "발행"이 있으면 무조건 중단하는 가드를 둡니다. 항상 **임시저장**까지만.
- 세션 만료(로그인 페이지로 튐)면 자동 로그인하지 말고 사람에게 알리고 중단.

---

## 1. 에디터 구조

- 글쓰기 URL: `https://blog.naver.com/{블로그ID}?Redirect=Write`
- 에디터는 **iframe 안**에 있습니다: `iframe#mainFrame` → `contentFrame()`으로 들어가서 작업.
  - 상단 저장/발행 바, 툴바, 본문이 **전부 이 프레임 안**에 있습니다.
- 본문 문단: `.se-text-paragraph` (문단 하나 = 이 요소 하나)
- 제목 영역: `.se-section-documentTitle`
- 본문 컨테이너(글자수 측정 등): `.se-content` (클래스명이 바뀔 수 있어 여러 후보로 측정 권장)

## 2. 확정 셀렉터 (실제 화면 진단으로 확인)

> 주의: `save_btn__bzc5B`처럼 뒤에 해시가 붙은 클래스는 네이버 업데이트 때 바뀔 수 있습니다.
> 가능하면 **aria-label**이나 **`se-*` 접두사**, **버튼 텍스트**로 잡는 게 안전합니다.

| 기능 | 안전한 셀렉터 | 비고 |
|---|---|---|
| 임시저장 버튼 | `button:has-text("저장")` (텍스트 "저장") | '발행'과 절대 혼동 금지 |
| 발행 버튼 | `button:has-text("발행")` | **누르지 말 것** |
| 임시저장 목록 열기 | `button[aria-label*="임시저장된 글 보기"]` | 상단 "99+" 카운트 버튼 |
| 목록의 각 글 | `button[class*="article_button"]` | 텍스트 = "[제목]…2026.08.03 00:20" |
| 목록의 삭제 버튼 | `button[class*="delete_button"]` | **제외 대상** |
| 문단서식 드롭다운(본문↔소제목↔인용구) | `button:has-text("문단 서식")` | 텍스트 "본문문단 서식 변경" |
| ↳ 드롭다운 옵션(소제목/인용구/본문) | `button.se-toolbar-option-text-button:has-text("소제목")` | 컨테이너 말고 **실제 옵션 버튼**을 잡아야 함 |
| 굵게 | `button:has-text("굵기 적용")` | 텍스트 "굵게굵기 적용" |
| 인용구 추가(빈 블록 삽입) | `button:has-text("인용구 추가")` | ↓ 함정 참고 |
| 구분선 추가 | `button:has-text("구분선 추가")` | |
| 이전 글 복구 팝업 확인/취소 | `.se-popup-button-confirm` / `.se-popup-button-cancel` | |

## 3. 반드시 알아야 할 함정 (여기가 핵심)

### 3-1. 네이버는 "프로그램으로 만든 선택 영역"을 무시한다
- `window.getSelection().addRange(range)`로 텍스트를 선택하고 굵게/서식을 적용하면 **아무 일도 안 일어납니다**(카운트만 올라가고 화면은 그대로).
- 반드시 **실제 마우스**(`page.mouse.down/move/up`)나 **실제 클릭**으로 만든 선택/커서만 인정됩니다.

### 3-2. 블록 서식(소제목·인용구·본문)은 "문단 전체"에 적용된다
- 소제목/인용구/본문은 문단 단위 서식이라, 문단 안 한 글자만 선택해도 **문단 전체**가 바뀝니다.
- 그래서 이들은 **텍스트 선택이 필요 없습니다.** 그 문단에 **진짜 커서만** 놓고(단일 클릭) 문단서식 드롭다운에서 고르면 됩니다.

### 3-3. 굵게는 "선택"이 필요하다 — 커서만 있으면 문단 전체가 굵어진다(함정!)
- 굵게는 인라인 서식이라 **선택 영역**에 적용됩니다.
- 그런데 아무것도 선택 안 한 채(커서만) 굵게를 누르면 **그 문단 전체가 굵어집니다.**
- 정답: **① 단어를 평범하게 타이핑 → ② 그 단어만 실제 마우스로 드래그 선택 → ③ 굵게 클릭.** (선택된 부분만 굵어짐)

### 3-4. 맥에서 Home 키는 선택 해제/줄 맨앞 이동이 안 된다
- `page.keyboard.press('Home')`이 맥에선 선택을 안 풀어서, 이어지는 Delete가 본문까지 먹어버립니다.
- 줄 맨앞으로 가려면 **`Meta+ArrowLeft`(Cmd+←)** 를 쓰세요. 커서만 두려면 트리플클릭 말고 **단일 클릭**.

### 3-5. 줄바꿈에 걸친 문구 선택은 "박스 중앙 훑기"로 하면 깨진다
- `getBoundingClientRect()`는 두 줄에 걸친 문구를 하나의 큰 박스로 주고, 그 세로 중앙을 가로로 훑으면 엉뚱한 범위가 잡힙니다.
- `range.getClientRects()`로 **줄별 사각형**을 얻어, 첫 줄 왼쪽(시작점) → 마지막 줄 오른쪽(끝점)으로 드래그하세요. (사람이 여러 줄 드래그하듯)

### 3-6. 인용구 블록에는 "출처 입력" 칸이 딸려 있다
- 인용구를 만들고 내용을 입력하면 커서가 인용구 안에 있고, 아래 "출처 입력" 칸이 붙습니다.
- 다음 작업으로 넘어가려면 **아래 방향키를 두 번**(ArrowDown ×2) 눌러 블록을 빠져나오세요.
- 참고: 툴바의 "인용구 추가" 버튼은 **기존 문단을 바꾸는 게 아니라 빈 인용구 블록을 새로 삽입**합니다. 기존 텍스트를 인용구로 만들려면 이 버튼 말고 **문단서식 드롭다운의 "인용구"** 옵션을 쓰세요.

### 3-7. 서식 있는 붙여넣기는 "진짜 클립보드 + 진짜 ⌘V"로
- 합성 paste 이벤트나 innerText 주입은 에디터가 거부하거나 서식을 잃습니다.
- 맥이라면 `osascript`로 시스템 클립보드에 **HTML flavor**로 적재한 뒤, 본문 클릭 → `page.keyboard.press('Meta+KeyV')`(진짜 ⌘V). 사람이 복붙하는 것과 동일해서 서식(소제목/인용구/구분선/볼드)이 그대로 들어갑니다.

### 3-8. 다른 기기(모바일)에서 저장한 글 불러오기
- 새 글 열 때 뜨는 "이어서 작성하시겠어요?" 팝업은 **그 브라우저의 로컬 자동저장**이라 모바일 저장 글에는 안 뜰 수 있습니다(불안정).
- 대신 상단 **"임시저장된 글 보기"(저장 카운트) 버튼**을 눌러 서버 저장함 목록을 열고, **제목이 일치하는 항목**(`button.article_button…`)을 클릭해 불러오세요. 계정이 같으면 모바일 저장 글도 PC에서 보입니다.
- 목록 항목 텍스트는 앞에 `[제목]` 딱지, 뒤에 날짜(`2026.08.03 00:20`)가 붙기도 하니 매칭 전에 떼어내세요.

## 4. 서식별 적용 순서 (요약)

- **소제목**: 문단에 단일 클릭(진짜 커서) → 문단서식 드롭다운 클릭 → "소제목" 옵션 클릭.
  - 마커 방식이면: 트리플클릭 선택 → Backspace로 빈 줄 → 드롭다운 "소제목" → 텍스트 타이핑.
- **인용구**: 위와 동일(드롭다운 "인용구") → 타이핑 → **ArrowDown ×2**로 출처칸 탈출.
- **구분선**: 그 자리(빈 줄)에 커서 → "구분선 추가" 클릭.
- **볼드(단어)**: 평범하게 타이핑 → 그 단어만 실제 마우스 드래그 선택(시작점→끝점) → "굵기 적용" 클릭.

## 5. 안정성 / 봇 탐지 회피

- 붙여넣기 자체는 사람도 흔히 하니 숨길 필요 없지만, **저장 "전"에 60~150초 '퇴고 체류'**(사람이 훑어보는 시간)를 두고 커서 곡선 이동/읽는 속도 스크롤을 흉내 냅니다. 저장 후엔 짧게만 머뭅니다.
- 서버가 확실히 아는 신호는 "에디터 열림 → 저장 요청"의 시간 간격과 글 분량입니다.

## 6. 무한루프/타임아웃 방어

- 마커를 찾아 순회 처리할 때, **같은 마커가 두 번 연속 잡히면(=진행 안 됨) 강제로 그 마커를 지우고 넘어가게** 하세요(안 그러면 무한 반복 + 헛타이핑).
- 전체에 **하드 타임아웃**(예: 2분)을 두고, 각 문단 작업 "시작 전"에 시간 체크 → 넘으면 저장 단계로.
