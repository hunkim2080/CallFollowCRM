## 2. 남은 7개 — 서버 작업 명세 (우선순위 순)

### (P1) 통화 요약 카드 · 상담함 + 채팅 — 빈칸 = "통화 내용 인입"
- **현황:** 앱은 통화 구간(📞 카드)을 채팅 타임라인에 이미 표시(`CallSegment`). **SMS 기반 요약**은 이미 됨
  (`/api/card-summary`, `/api/conversation-summary` 존재 → `AiSummaryEntity.cardSummary`/`conversationSummaryJson`).
  - 진짜 빈칸: **통화 음성/내용**이 서버로 안 들어옴. 현재 요약은 문자만 본다.
- **요청:** 에이닷 통화요약 텍스트(사장님이 공유) → 서버로 인입 → 통화 내용까지 반영한 요약.
  - 후보 흐름: 앱이 에이닷 공유 텍스트를 받아 서버에 POST → conversation-summary 입력에 통화 turn 추가, 또는 전용 `/api/call-summary`.
  - 앱 측 저장소는 `CallSummaryEntity`(callSummaryRepository.observeByCustomer) 존재 → 채워주면 표시 가능.
  - 출력: 불릿 몇 줄 + (선택) "후속 문자 초안".
- 현황판: 상담함 "통화 요약 카드" 🔷→✅.

### (P2) 시공접수서 (고객 자가확인 폼) · 견적·접수서
> ⚠️ **정정(2026-06-01): 이전 판의 "주소·시공범위·연락처 입력" 설명은 부정확했음.** 폼은 반드시
> **프로토 `ringgo-redesign.html` 의 `openQuote` 함수(고객용 시공접수서 화면) 그대로** 만든다.
> §0 룰 — 추상 설명 말고 프로토 코드 1:1.

- **현황:** 프로토에 **완성된 접수서 화면(`openQuote`)이 있음** — 그대로 옮길 것.
- **프로토 실제 폼 = "3가지만 확인":**
  1. **시공일** — 사장님이 정한 확정 시공일을 **표시만**(읽기 전용, "확정" 배지). 고객 입력 X.
  2. **견적 내역** — 사장님이 만든 항목·합계(부가세 별도)·계약금을 **표시만**. 고객 입력 X.
  3. **연락처·현장 정보** — 고객 입력 = **전화번호 + 현장 주소(검색) + 동/호수(선택) + 현장 메모(선택)**.
  - ＋ (선택) **유입 경로 설문** ("어떤 경로로 알게 되셨어요?" 네이버/인스타/구글/기타 → 키워드/카테고리). 마케팅용, 건너뛰기 가능.
  - ＋ 동의 체크 ("위 내용 확인, 시공 접수합니다") → "접수 완료하기". 제출 전 "이 주소가 정확한가요?" 확인.
- **❌ 프로토에 없는 것 (넣지 말 것):** 고객이 **평수·시공 부위·가능 시간을 직접 입력**하는 칸.
  평수·부위는 **사장님이 견적에서 이미 정한 값**이라 고객한테 다시 안 물어본다. (현재 서버 폼에 잘못 들어가 있음 → 제거)
- **제출 payload (프로토 `finalizeQuote` 기준):** 전화번호, 주소(+동/호수), 메모, 유입경로(src). 평수/부위 입력값 X.
- 앱 연동 지점: 사장님이 채팅에서 [📋 접수서 링크] → 서버 발급 URL 을 SMS 본문에 prefill(앱 #10 완료) → 사장님 ▶ 직접.
  제출되면 서버 → 앱(GET status polling)으로 "접수서 작성됨" + payload(주소·메모·유입).
- 의존 항목: **"접수서 작성 리마인드"**(상담함) 는 이게 생겨야 가능. 앱 측 리마인드 인프라(아래 4번)는 이미 있음 → 접수서 발급/제출 시각만 주면 앱이 카드로 띄움.

### (P2) 팀 관리 (99k 요금제) · 더보기
- **현황:** 앱 미구현. 다계정/권한 = 서버 필수.
- **요청:** 팀원 초대·역할·현장 배정 모델 + API. 99k 티어 게이팅.
- 의존 항목: **"팀원 현장사진 알림"**(상담함) 은 팀 모델 + 사진 업로드 채널이 생겨야 가능.

### (P3) 접수서 작성 리마인드 · 상담함 (← 시공접수서 후)
- 앱은 **리마인드 인프라 재사용 가능**: 정기문자/시공안내/견적회신과 동일 패턴
  (`recurring_message_log` + 홈 카드 + 보내기/넘기기). 서버가 "접수서 미작성 + 발급 N일 경과" 신호만 주면 앱이 카드화.

### (P3) 팀원 현장사진 알림 · 상담함 (← 팀 관리 후)

## 3. 서버가 이미 구현한 것 (`server/main.py` 확인됨 — 점검만)
앱이 응답 없으면 조용히 숨기므로, **엔드포인트는 있으나** 실제 end-to-end 로 채워지는지 확인 부탁:
1. **`POST /prepare-reply`** + `GET /suggestions/{phone}` — AI 추천 답변 칩.
2. **`POST /api/card-summary`** — 홈/일정/고객상세 카드 ✨ 한 줄 요약(`AiSummaryEntity.cardSummary`).
3. **`POST /api/conversation-summary`** — ChatScreen 대화 요약(`conversationSummaryJson`).
4. **`POST /api/next-action-suggest`** — ChatScreen "다음 액션" 박스.
5. **`POST /api/refine`** — ✨ 다듬기(Gemini). **위 (이미 완료) 참고.**
6. **`POST /api/address-resolve`** — §13 아파트 주소 resolve.
→ 즉 요약/추천/다듬기 파이프라인은 서버에 **이미 존재**. 빈칸은 (a) 통화 내용 인입, (b) 시공접수서, (c) 팀 관리.

## 4. 앱이 이미 갖춘 "리마인드/발송 대기" 인프라 (서버가 재활용하면 좋음)
이번 세션에 만든 **공통 패턴** — 서버 신호를 홈 카드로 띄우기 쉬움:
- DB v25 `recurring_message_log` (ruleId, customerId, occurrenceDayStartMs, status) — 보냄/넘김 dedupe.
  - 양수 ruleId = 정기문자, **음수 sentinel** = 시스템 리마인드(-1 D-1, -2 도착, -4 견적회신). 새 리마인드는 -5, -6… 추가 가능.
- 홈 `SimpleDueCard` + 전용 목록 화면 + `[보내기]=ChatDraftStore prefill 후 채팅 진입` / `[넘기기]=DISMISSED 로그`.
- **정책 고정:** 자동발송 X. 모든 발송은 사장님이 채팅에서 ▶ (SEND_SMS 명시 액션). 서버도 이 정책 존중.
