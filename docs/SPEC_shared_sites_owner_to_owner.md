# 기획 — 사장 ↔ 사장 "공유 현장" (RING-GO 사용자끼리 일정 공유)

작성: 2026-06-06 · 사장님 요청("우리 앱 쓰는 사장끼리, 같이 하기로 한 현장을 공유하고 싶다. 깊게 기획해줘")

---

## 0. 한 줄 정의
**한 현장(시공 건)을 두 명 이상의 RING-GO 사장님이 같이 보고·기록할 수 있게 하는 기능.**
서로의 사업 전체는 절대 안 보이고, **딱 그 공유한 현장 하나만** 같이 본다.

---

## 1. 왜 필요한가 — 실제 상황 3가지
1. **공동 시공** — 큰 현장을 둘이 나눠서 (예: A는 욕실, B는 주방). 같은 날·같은 주소.
2. **하청/외주** — A가 받은 일을 B에게 일부 맡김. A는 진행상황을 봐야 하고, B는 현장 정보(주소·시간·범위)가 필요.
3. **품앗이/일손 부탁** — 바쁜 날 B가 A 현장 하나를 대신 가줌.

공통점: **"이 현장 하나"에 대한 정보(날짜·주소·시공범위·메모)와 진행(출발/도착/완료·사진·메모)을 둘이 같이 본다.**

---

## 2. 핵심 원칙 (절대 어기면 안 됨)
- **벽(wall):** 공유는 **그 현장 1건만**. 상대 사장의 다른 고객·대화·AI요약·매출·전화번호부는 **절대 안 보임**.
- **보존:** 공유를 끊어도 상대가 올린 사진·메모는 **지우지 않음** (소유자 쪽엔 남음). 끊김 = "상대가 그 현장을 더는 못 볼 뿐". (이미 [[project-team-management]] 배정 해제와 동일 철학)
- **자동발송 없음:** 공유·알림은 떠도, 고객에게 가는 문자는 사장님이 직접.
- **명확한 역할:** 누가 "현장 주인(고객 보유)"이고 누가 "협업 사장"인지 분명히.

---

## 3. 어떻게 연결하나 (가장 중요한 설계)
**전화번호로 초대 → 상대가 앱이 있으면 "인앱 공유", 없으면 "웹링크"(지금 팀원 기능) 자동 분기.**

- 사장 A: 현장에서 **"다른 사장님과 공유"** → 상대 전화번호 입력.
- 서버가 그 번호가 **RING-GO 가입 사장인지** 확인:
  - **가입자(앱 있음)** → 상대 B 앱에 "OO 사장님이 [현장] 공유했어요 — 수락?" 푸시. 수락하면 B 앱 안 **"공유 현장"** 칸에 등장.
  - **미가입(앱 없음)** → 지금처럼 **웹링크** 발송(기존 팀원 흐름 그대로). 나중에 그 사람이 가입하면 인앱으로 승격.

> 장점: "현장 공유하기" 버튼 하나로 앱 유무 상관없이 동작. 기존 팀 기능(토큰·이벤트·사진)을 **80% 재사용**.

---

## 4. 공유되는 것 / 안 되는 것 (기본값 = 추천)

| 항목 | 공유? | 비고 |
|---|---|---|
| 현장 날짜·시간·기간 | ✅ | |
| 현장 주소 | ✅ | 협업 핵심 |
| 시공 범위/전달 메모 | ✅ | "대표님 전달사항"처럼 |
| 출발/도착/완료 진행 | ✅ 양방향 | 둘 다 누르고 둘 다 봄 |
| 현장 사진 | ✅ 양방향 | 둘 다 올리고 둘 다 봄 |
| 현장 메모(특이사항) | ✅ 양방향 | 리플 가능(기존 기능 재사용) |
| **고객 전화번호** | ❓ **결정 필요** | 직접 통화 필요 vs 사생활 |
| 고객과의 **대화/문자** | ❌ | 사생활 |
| AI 요약·추천 답변 | ❌ | 현장 주인 것 |
| **정산(누가 얼마)** | ❓ **결정 필요** | v1 제외 추천, v2 "분배 메모" |
| 상대의 다른 고객 전부 | ❌ 절대 | 벽 |

## 5. 두 사장 화면 흐름

### A (현장 주인 · 초대하는 쪽)
1. 일정/고객카드 → **"다른 사장님과 공유"** → 번호 입력 → 초대.
2. 고객카드에 **"공유 중 · B 사장님"** 표시 + B가 올린 사진/메모/진행이 그대로 보임(지금 팀 기능과 동일).
3. 공유 해제 버튼(= 배정 해제처럼, 사진·메모는 보존).

### B (협업 사장 · 초대받는 쪽)
1. 푸시: "OO 사장님이 [강동 천호동 현장] 공유했어요" → **수락/거절**.
2. 수락 시 B 앱 **하단/더보기에 "공유 현장" 칸** 생김 (B 자기 고객들과 **분리**된 별도 영역).
3. 그 현장 들어가면: 날짜·주소·시공범위·전달메모 보기 + **길찾기, 사진 올리기, 메모 쓰기, 출발/도착/완료**.
4. B는 A의 다른 고객을 **전혀 못 봄**.

---

## 6. 단계별 계획

### 지금 당장 (코드 0) — 임시 우회
A가 B를 **"팀원"으로 추가**(더보기 → 팀 관리) → B는 **웹링크**로 그 현장 보고 사진·진행 올림.
→ 된다. 단 B가 앱 사장인데도 웹을 써야 하고 "팀원"으로 보여 어색함.

### Phase 1 (MVP) — 인앱 공유 (앱↔앱)
- 서버: 번호로 "앱 사장인지" 판별 + 공유 레코드(기존 team_members/events/photos 재사용, "앱 사용자" 플래그).
- B 앱: "공유 현장" 목록 + 보기/사진/메모/진행(기존 SitePhoto·events API 재사용, 토큰 대신 내 번호로 인증).
- A 앱: "다른 사장님과 공유" 버튼 + 진행 표시(기존 그대로) + 해제(보존).
- 푸시: 초대·수락·진행 알림(기존 TeamEventCenter 재사용).

### Phase 2 — 협업 강화
- 고객 번호 공유 토글(사장님 선택).
- 정산 "분배 메모"(누가 얼마, 단순 기록 — 자동계산 X).
- 메모 양방향 리플(이미 있음) 연결.

### Phase 3 — 일정 충돌 방지(선택)
- 서로 **바쁨/한가함만**(상세 X) 보여 더블부킹 방지.
- 현장 3명+ 그룹 공유.

## 7. 기술 메모 (구현 시)
- 식별: 사장 = bizPhone. 서버에 "가입 사장(bizPhone)" 디렉터리 필요(없으면 가벼운 register-me).
- 재사용: `team_members`/`team_member_events`/`team_site_photos`/`schedule-snapshot` 그대로. member.phone == 상대 bizPhone 이면 "앱 사장" 분기.
- 신규(앱 B측): `SharedSiteRepository`(`/api/shared/with-me?phone=B` 폴링) + "공유 현장" 화면(사진/메모는 기존 repo 재사용).
- 신규(서버): 번호→가입여부 조회, 초대 수락/거절 상태, with-me 목록.
- 벽 보장: B 인증은 자기 번호 + 그 현장 권한만. 다른 현장 요청은 403.

## 8. 사장님 결정 필요 (Phase 1 시작 전)
1. **고객 전화번호**를 상대 사장에게도 공유? (직접 통화 가능 vs 사생활 보호)
2. **관계 형태**: 한 명이 현장 주인·다른 한 명은 협업(추천, 단순) vs 완전 대등(둘 다 동등 편집)
3. **정산(돈)**: v1 제외(추천) vs 분배 메모 포함
4. **이름**: "공유 현장" vs "함께 하는 현장" vs 다른 표현
