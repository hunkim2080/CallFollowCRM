## 판정 기준

| 항목 | ✅ 정상 | 🟡 지켜보기 | 🔴 손봐야 함 |
|---|---|---|---|
| 화면 멈춤 | 1.5초 미만 | 1.5~5초 (사장님이 "버벅인다") | 5초 이상 (안드로이드가 앱을 죽임) |
| 반복 배수(총 조회 ÷ 서로 다른 건수) | 1.5배 미만 | 1.5~4배 | 4배 이상 |
| 메모리 증가 | 50MB 미만 | 50~100MB | 100MB 이상 |

**'총 횟수'가 아니라 '반복 배수'로 보는 이유**: 사진문자가 많은 폰인 건 죄가 아니다.
같은 걸 계속 되묻는 게 죄다. 총 횟수만 보면 둘을 구분 못 해 엉뚱한 곳을 고치게 된다.

**5초의 근거**: 안드로이드는 화면이 5초간 입력에 응답하지 않으면 "응답 없음"으로 판단해 앱을 종료한다.
사장님이 말한 *"10초쯤 지나면 그냥 꺼져"* 가 정확히 이것이었다.

## 검진기가 아직 못 보는 것 (다음에 보탤 것)

- **"이전 대화 N개 더 보기" 탭 시점의 멈춤** — 버튼 위치를 좌표로 눌러야 해서 아직 자동화 안 함.
  당장은 폰에서 직접 누르고 `adb logcat | grep Skipped` 로 확인.
- **크래시·응답없음 자동 수집** — 지금은 사장님이 말씀해주셔야만 안다. 앱이 스스로 남기게 하는 게 다음 숙제.

## 이 문서를 쓰는 규칙

1. 폰을 꽂을 일이 생기면 **검진기를 먼저 돌리고**, 결과를 위 "실측 이력"에 한 줄 추가한다.
2. 성능 관련 수정을 하면 **고치기 전/후 숫자를 둘 다** 적는다. "고쳤다"는 말만 남기지 않는다.
3. 한도·지연·중복방지(숫자 낮추기)로 막은 건 **"아직 안 고침"** 으로 적는다.
   — 실제 사고: MMS 조회 폭주를 3번에 걸쳐 `2000→500`, `debounce 250ms`, `dedup 60초` 로 눌렀지만
   구조(번호 하나당 500번 조회)는 그대로여서, 데이터가 늘자 다시 터졌다.
