# 일당/협업 현장 흐름 + 일당 마켓 — 기획 & 핸드오프

작성: 2026-06-11 · 사장님(junjun) 구상 → 안드로이드 Claude 정리. 맥미니 Claude 핸드오프 포함.

---

## 0. 왜 (비전)

사장님 실제 루틴 — **직원이든 협업 일당사장이든 흐름이 같다**:
> 출발 → 도착(+현장사진 보고) → 작업 → 철수(완료) → [협업] 계좌 → 사장이 정산(입금)

목표: **링크만 보내면 처음 하는 사람도 우리 앱에서 관리/이용**하게 → 번호 기준 데이터가 쌓임 →
잘하는 일당을 골라 부르는 **"시공자 SNS / 일당 마켓"** (경력 없는 사람 나와 난감한 문제 해결).

참여자(일당/협업사장)가 이걸 쓰는 이유(=포인트):
1. **돈을 빨리·확실히** — 완료·계좌를 앱으로 = 즉시 정산 + 분쟁 방지 기록. (즉효, 제일 강력)
2. **내 이력·평판이 쌓여 다음 일감** — 현장마다 +1, 사진, (2단계)별점. (장기, 마켓 씨앗)
3. **협업 사장은 본인도 사장** — 본인 일 관리에도 앱이 도움. (양면 확산)

> 초반엔 포인트1(돈)만 진짜다. 부르는 사장이 "앱으로 완료=바로 입금" 규칙을 밀어 부트스트랩.
> 평판/마켓은 데이터 쌓인 뒤 힘을 받음.

## 1. Phase 1 범위 (확정)

**"완료·계좌 = 정산 스위치 + 번호별 이력 자동 적립"** 만.
- (결정1) 완료·계좌만. 출발/도착·사진은 1.5단계.
- (결정2) 계좌는 그 번호에 저장 → 다음 현장부터 자동채움(참여자 본인용).
- (결정3) 이력(현장 수·최근일)만. 사장 사적 별점은 2단계.

## 2. 한 현장 시나리오

```
사장: 일정 잡고 → 그 현장에 일당/협업사장 넣기 → 링크 발송(또는 이미 협업 중)
일당: 링크 탭 → 웹 화면(오늘 현장·시간·내 구역)
일당: [✅ 끝났어요·계좌 보내기] → 은행·계좌·예금주 입력 → 보냄
사장 상담함: "박일당 완료 · 국민 123-456(박일당)" [계좌복사] [💸 입금했어요]
사장: 송금 후 [입금했어요] → 정산 "일당 지급 –15만원" 자동기록 + 그 번호 이력 "정산완료✓"
일당 화면: "입금됐어요 ✓" + "내 이력: 현장 6곳"
```

## 3. 화면

### 3-1. 참여자(일당) 웹뷰 — **서버가 렌더(설치 X)**
기존 팀원 웹뷰(`/team/member/{token}`) 확장.
- 상단: 오늘 현장(주소·시작시간·내 구역 라벨). **고객 전화/대화 절대 미노출 — 안전 라벨만.**
- 핵심 버튼: **[✅ 끝났어요 · 계좌 보내기]** → 은행/계좌/예금주 입력(저장된 값 prefill) → 제출.
- 하단: **내 이력** — 함께한 현장 N곳 · 최근일. (본인 것이 쌓이는 느낌)

### 3-2. 사장 앱 — **안드로이드**
완료 알림(상담함):
- "○○ 작업 완료 · 현장라벨 · 계좌 은행 번호(예금주)" + **[계좌 복사]** + **[💸 입금했어요]**
- [입금했어요] → 정산에 **"일당 지급 –N만원" 지출 자동 기록** + 서버에 paid 표시.
- 금액: 배정 시 일당 정해졌으면 prefill, 아니면 입금 시 입력.

배정/초대 화면:
- 그 번호의 **이력 카드**: "함께한 현장 6곳 · 최근 6/10" (서버 조회). 경력 가늠용.

## 4. 데이터 모델 (번호 기준, 서버)

`laborer`(키 = 전화 끝 8자리):
- `completed_count`, `last_worked_at`, `sites: [{ label, date, photos[] }]` (고객정보 제외, 안전 라벨만)
- `saved_account: { bank, account_no, holder }` (참여자 본인 자동채움용 — 사장에겐 완료 시점에만 노출)
- (2단계) `private_ratings`(부른 사장별 사적 별점/메모), (3단계) `public_profile`(동의 기반)

## 5. app ↔ server 계약

### 맥미니(서버) 신규
1. **참여자 웹뷰 [완료·계좌]**: 웹뷰에 버튼 + `POST /api/labor/complete`
   `{ token, bank, account_no, holder }` → ① 그 배정 완료 기록 ② **owner-events 에 `completed` 이벤트 + account payload**(이미 협업 progress 형식 있음 — 팀/일당 배정 경로에도) ③ 번호 이력 +1 적립 ④ 계좌 저장.
2. **번호 이력 조회**: `GET /api/labor/history?phone={끝8자리}` →
   `{ count, last_worked_at, sites:[{label, date, photos[]}] }` (고객 전화·대화 **절대 미포함**).
3. **계좌 자동채움**: 웹뷰가 그 token/번호의 `saved_account` prefill.
4. **입금 완료 표시(옵션)**: `POST /api/labor/paid { token|event_id }` → 이력에 정산완료 마크.

### 안드로이드(앱) — 나(이 Claude)
- 완료 알림에 **[계좌 복사] + [입금했어요]** → 정산 `일당 지급` 지출(ManualCash) 자동 기록 + (가능하면) `/api/labor/paid` 호출.
- 배정/초대 화면에서 `/api/labor/history` 불러 **이력 카드** 표시.
- (기존 CollabEventCenter / owner-events 알림 통로 그대로 재사용.)

## 6. 개인정보·안전 (중요)
- 번호 기반 기록은 **서버에만**. 고객 전화번호·대화·계약 내용은 **참여자/이력 어디에도 노출 금지**(안전 라벨만).
- 공개 평판/별점은 **2단계+ 동의** 받고. 1단계 별점은 사장 사적용(공개 X).

## 7. 단계
- **1 (지금):** 완료·계좌 = 정산 스위치 + 번호별 이력 적립.
- **2:** 이력 카드 고도화 + 사장 사적 별점.
- **3:** 동의 기반 공개 프로필 → 다른 사장도 보고 부르기 = 마켓("시공자 SNS").
