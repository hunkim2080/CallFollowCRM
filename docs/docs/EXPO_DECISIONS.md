# 박람회 팀 시공 — 사장님 확정 사항 (2026-07-22)

> 원 설계: `docs/PLAN_expo_team.md` (android + Fable5, 07-21).
> 이 문서는 그 §"사장님이 정할 것" 8개에 대한 **사장님 답변 기록**이다.
> **android / cowork 둘 다 이 문서를 스펙으로 따른다.** 여기 없는 항목은 아직 미확정 → 지어내지 말 것(CLAUDE.md §8).

---

## ✅ 확정 1 — 박람회는 "별관"이다 (정산 격리)

- **박람회 카테고리는 정산 캘린더에 적용되지 않는다.** 매출·미수금·입금 등 **정산 집계에서 완전히 제외**.
- 앱 안에서도 **거의 별도로 운영하는 페이지**로 본다 (설정에서 켜는 박람회 모드 = `ExpoScreen`, 코어 UX 불변).
- 이유: 박람회 계약은 총액이 팀 전체 몫이고 분배 전까지 "내 돈"이 아니다. 평소 정산에 섞이면 사장님 매출 숫자가 거짓이 된다.

### ✅ 격리 수준 = **완전 격리** (2026-07-22 확정)
분배 확정 후에도 그 고객은 **박람회 페이지 안에만 존재**한다. 평소 고객카드·시공 캘린더·정산 어디에도 뜨지 않는다.
- 사장님 판단: "고객카드엔 뜨되 정산에선 빠진다"는 **하이브리드는 나중에 더 복잡해진다.** 예외 규칙을 앱 곳곳에 심는 셈.
- 시공 날짜 충돌 걱정 불필요 — **박람회 뛰는 사람은 그 기간 박람회 일정만 뛴다.** 평소 일정과 겹칠 일이 없음.
- 박람회 사용자는 애초에 **박람회 탭을 쓰려고 시공막내를 설치**하는 층으로 본다.
- 대가(기록): 기존 `IntakeSyncManager` 재활용 이점이 사라져 **팀원 앱에 박람회 전용 목록·캘린더·상세를 새로 만들어야 함**. 또 "행사 후 일상 CRM으로 잇는 다리"도 없어짐 → 필요해지면 훗날 **[내 고객으로 가져오기]** 버튼 1개로 따로 붙인다(지금 섞지 않는다).

## ✅ 확정 2 — 분배 풀은 "팀별"

- 부스 전체를 한 통에 넣지 않는다. **자기 팀 것만 자기 팀 안에서 나눈다.**
- 따라서 데이터 모델의 분배 단위 = `team_id`(부스 아님). 한 부스에 여러 팀이 있어도 계약서는 **작성 시점의 팀**에 귀속된다.
- 서버: `expo_contracts.team_id` 필수. 분배 엔진(LPT)은 team 단위로 독립 실행.
- 앱: 상담원이 계약서를 열 때 자기 팀이 자동 결정돼야 함(팀 미지정 상태로 계약서 발급 금지).

## ✅ 확정 3 — 계약서는 "상품 카탈로그 체크" 방식

프로토(`ringgo-redesign.html`)에 박람회 계약서가 없으므로, 아래가 **신규 확정 스펙**이다.

1. **상품명을 미리 등록해둔다** — 업체마다 파는 상품이 다르므로 계약서를 자유 입력으로 만들지 않는다.
2. **고객과 함께 화면을 보면서 체크**하는 형식 — 등록된 상품 목록에서 고르는 방식.
3. **마지막에 서명** — 고객 손글씨 서명.
4. **한 부씩 저장** — 제출 시 계약서 스냅샷을 굳혀 보관하고, **고객에게도 사본**을 준다.
5. **계약금은 현장에서 결정** — 계약금 입력란을 **넣을지 말지 상담원이 그 자리에서 켜고 끌 수 있어야** 한다(고정 필수 아님).
6. **법적 수준: 서명 + 개인정보 수집·이용 동의** (사장님 확정). 기존 시공접수서 동의문 세트를 재활용한다.

---

## ✅ 확정 4 — 팀 = "방", 방장이 계약서를 준비한다

- **방장(팀장)이 방을 개설하고 팀원을 초대한다.** 소유권 개념은 딱 그 정도 = **방장**.
- **방장이 계약서를 준비한다** — **시공 상품 목록** + **서비스 항목**을 미리 기재해 둔다.
- **팀원 계약서에는 방장이 기재해 둔 그 상품 목록·서비스 항목이 그대로 보인다.** (상담원 개인이 따로 만들지 않음)
- 서버: `expo_products(room_id, kind: 'product'|'service', name, unit_price?, sort)` — 방 단위 1벌.

### ✅ 확정 5 — "우리 팀 수집된 접수서 보기"

방 안에 **팀 전체 계약 현황을 중간중간 확인**하는 목록이 있어야 한다. ("행사 도중에 좀 보고 싶을 때가 있잖아")
- 노출: **어떤 시공 상품인지 + 얼마짜리인지** + 접수 시각/상담원.
- **개인정보 마스킹: 휴대폰 번호 뒷 4자리를 가려서 노출** (예: `010-1234-****`).
- 팀원 누구나 볼 수 있는 팀 공용 화면(분배 전에도 보임).

### ✅ 확정 6 — 분배 후 팀원별 시공 진행률

- 분배가 끝나면 **팀원마다 시공 진행률 %** 를 표기. 하나씩 처리해 나갈 때마다 퍼센트가 올라간다. **프로그레스 바**.
- 팀 보드에서 서로의 진행률이 보인다(누가 밀리는지 한눈에).

---

## ✅ 확정 7 — 단가 사전등록 + 총액 할인

- **팀장이 초기 세팅 시 상품 단가를 미리 박는다.** (`expo_products.unit_price` 필수 입력)
- **현장 할인은 상품 단가를 건드리지 않는다** — 보통 **마지막 총금액에서 할인**하므로, 계약서에 **[총액 할인]** 란을 두어 최종 합계에서 차감한다.
  - 계약서 계산: `상품합계 = Σ(단가×수량)` → `최종금액 = 상품합계 − 할인` (+ 계약금란은 현장 on/off, 확정3).

## ✅ 확정 8 — 진행률 눈금 2종

분배받은 접수서를 기준으로 팀원별 **두 개의 프로그레스 바**를 표기:
1. **일정 등록률** = 일정에 넣은 건수 / 분배받은 건수
2. **시공 완료율** = 시공 완료 건수 / 분배받은 건수

- 상태 전이: `분배됨(assigned)` → `일정등록(scheduled)` → `시공완료(done)`. 눈금1은 scheduled+done, 눈금2는 done 만.

## 확정에 따른 설계 영향 (cowork 메모)
- **완전 격리** — 박람회 데이터는 `expo_*` 테이블에만 산다. 기존 `submissions`/고객/정산 테이블에 **아예 넣지 않는다**(플래그로 거르는 게 아니라 애초에 안 섞음). 규칙이 하나라 예외가 안 생김.
- **팀별 분배** 확정으로 분배 엔진 입력이 단순해졌다(부스 전체 최적화 불필요).
- **상품·서비스 카탈로그**: `expo_products(room_id, kind, name, unit_price?, sort)` — 방장이 1벌 관리.
- **팀 접수서 목록 API**: 방 단위 조회 + **서버에서 전화번호 뒷4자리 마스킹해서 내려준다**(앱에서 가리는 게 아니라 서버가 안 보냄 = 유출 경로 차단).
- **진행률**: 팀원별 `완료 건수 / 분배받은 건수`. 계약 상태 전이(분배됨→일정확정→시공완료)를 `expo_contracts.status` 로 관리.
- **서명·사본**은 접수서 영수증 페이지(`openQuoteDoc` 패턴) 재활용 가능.

## ✅ 확정 9 — 계약서는 "실시간 양방향" (2026-07-22 오후, 사장님 재설계)

> Phase 1(고객이 자기 폰에서 상품 고르고 제출 = 단방향)에서 **방식 전환**. 상세 핸드오프: `docs/SERVER_HANDOFF_expo_phase4_realtime.md`.

- 상담사·고객이 **마주 앉아** 상담. 각자 폰만 있고 화면을 같이 못 봄 → **화면을 실시간으로 맞춰 보며 대화**.
- **고객 = viewer.** QR 찍으면 상담사가 체크하는 걸 실시간으로 봄. 상품 선택은 **상담사가**(고객 아님).
- **상담사 조작 위치 = 시공막내 앱 안(네이티브).** (사장님 확정: 앱 안. 사장님이 앱 쓰는 사람이라.)
- **고객이 직접 입력 = ①고객정보 ②서명** 뿐.
- **시공주소 = 다음(카카오)지도 방식** — 우리 앱 주소수집과 동일. 아파트명·동호수 구조화. (고객 웹에서 입력)
- 완료 시 **카톡 공유 / PDF 저장**(계약 내용 보관).
- 역할: 실시간 동기화·고객 웹페이지·PDF·주소 = **서버(코워크)**. 상담사 네이티브 화면·접수서 네이티브·공유시트 = **앱**.

### ✅ 확정 5 보강 — "우리 팀 접수서"는 앱 네이티브 (웹뷰 ❌)
- **앱에서 바로** 열림(인터넷 웹뷰 아님). 목록 = **이름 + 시공내역** + **계약자(누가 계약했나)**.
- 시공내역 **클릭 시 펼쳐** → **아파트명 + 동호수**(상세주소).
- 서버가 submissions 에 `apartment`·`dong_ho` 내려주면 앱이 네이티브로 렌더. (receiptUrl 은 PDF·공유용으로만)
