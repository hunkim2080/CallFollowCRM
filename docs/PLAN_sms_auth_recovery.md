# PLAN — SMS 인증(OTP) + 번호변경/복구 (데이터 안전의 뿌리)

확정: 2026-08-13 사장님. 설계 = 3층 방어. 신중·단계적 롤아웃(기존 사용자 락아웃 방지).

관련: `docs/ANDROID_HANDOFF_signup_auth.md` · 세션토큰 배선 commit 08d174e · 데이터안전 감사

---

## 왜 (문제)

- 지금 로그인 = **번호만 대면 통과(무인증)** → 남의 번호 알면 남의 데이터 봄(IDOR). 홍보 전 필수 수정.
- 데이터가 폰 한 대에만 → 재설치/기변/데이터삭제 시 소실. 서버 백업 필요하나, **"이 데이터 주인이 진짜 너냐"를 증명할 인증**이 먼저 있어야 안전하게 복구됨.

## 원리

**"그 번호로 문자 보내 → 그 문자를 받는 사람 = 그 번호 주인"** 확인. 일회용 6자리 코드(비번처럼 미리 정한 암호 아님, 유출돼도 곧 만료).

## 3층 방어 (어떤 경우든 데이터 안 잃게)

| 상황 | 해법 | 비고 |
|---|---|---|
| **폰만 바꿈·번호 유지** (대부분) | SMS 인증 → 자동 복구 | 비번·이전 불필요 |
| **번호 바꿈 + 미리 이전** | **방법 A**: 앱 안 "번호 변경"(로그인 상태서 새 번호 인증) → 데이터 새 번호로 이전 | 카톡·왓츠앱 방식. 옛 번호 버리기 전에 |
| **번호 바꿈 + 이전 깜빡** | **방법 B**: 미리 설정한 **복구 비번/코드** → "옛 번호 + 비번"으로 복구 | 사장님 아이디어. 안전망 |

- **비번은 필수 아님** — 안전망 옵션. 대부분은 SMS로 끝.

## 구현 조각 (대부분 이미 배선됨)

### ✅ 이미 된 것 (commit 08d174e)
- 앱: 세션 토큰 저장(EncryptedSharedPrefs) + 모든 api.si0in.kr 요청에 `Authorization: Bearer` 자동 부착(19 저장소, Net.builder) + 401 시 재로그인.
- 지금은 **스위치 OFF**(SMS_SIGNUP=false)라 동작만 안 함(무해).
- 서버: `_send_sms_solapi` 존재(자동 SMS 금지 정책의 **예외 = 인증 코드**).

### 🔲 남은 것
1. **SOLAPI 실계정** — 문자 발송 업체. **⚠️ 사장님이 가입·결제·API키 발급** (외부, 나·코워크 대행 불가). 발송 단가 실측(건당 10~20원).
2. **서버(코워크)**: `POST /auth/request-code`(번호→6자리 생성+SOLAPI 발송+임시저장 3분) · `POST /auth/verify-code`(번호+코드→토큰 발급). `AUTH_ENFORCE` 플래그.
3. **앱(android)**: 로그인 화면에 번호→코드 입력 흐름 · SMS_SIGNUP=true. (토큰 배선은 이미 됨)
4. **방법 A**: 앱 "번호 변경"(설정) + 서버 이전 엔드포인트(옛→새 번호로 owner 데이터 이관).
5. **방법 B**: 복구 비번 설정(앱/서버 저장, 해시) + "옛번호+비번" 복구 엔드포인트.
6. **서버 자동 백업**: 앱이 데이터(고객·돈·일정=글자, 가벼움) 주기 백업 → 인증되면 복구. (별도 PLAN, 데이터안전 감사)

---

## ⚠️ 롤아웃 순서 (락아웃 방지 — 매우 중요)

**절대 인증부터 강제(AUTH_ENFORCE=1)하면 안 됨** — 기존 사용자는 토큰이 없어 전부 튕김.

1. SOLAPI 붙이고 request/verify-code 엔드포인트 배포 (아직 강제 X).
2. 앱 SMS_SIGNUP=true 배포 → 사용자가 앱 켤 때 **소프트 로그인**으로 토큰을 조용히 확보(며칠~1주 유예).
3. 대부분 토큰 확보 확인되면 → 서버 `AUTH_ENFORCE=1`.
4. 방법 A·B는 그 위에 얹기.
