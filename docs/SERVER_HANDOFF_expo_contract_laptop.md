- 박람회 계약서를 어르신 고객이 **폰 작은 글씨**로 보고 서명하기 힘들다는 의견.
- 사장님이 **노트북 큰 화면에서 항목·금액을 전부 정하고** → **고객 전화번호 입력 → 고객에게 계약서 전송** → 고객이 자기 폰/태블릿으로 열어 **정보 입력·서명**.
- 스타일 = **카톡 아님 → 현대 계약서(전자계약서) 스타일**. 큰 글씨·고대비·반응형(태블릿/노트북 우선).
- **카톡 전송 안 함(유료)** · **실시간 코뷰 불필요** · **업자(사장님) 노트북에서만 구동** · **지금 QR 실시간 방식은 그대로 남김**(하위호환).

```
[사장님 노트북 웹]  줄눈/실리콘/청소 체크 + 재질(폴리우레아·케라폭시) + 금액(줄눈·청소 2그룹) + 입금자·특이사항

                        → 계약서 보관(PDF) · submissions·달력 반영 (기존과 동일)
```

## 4. ⚠️ 열린 결정 — 문자 전송 방식 (사장님 판단 필요)
현 서버 정책 = **"자동 SMS 발송 절대 금지 · 서버는 URL만 발급, 발송은 앱 ▶ 직접"**(접수서/팀초대/미러 전부). 근데 새 흐름은 **사장님이 노트북**에 있어 폰 앱 ▶ 발송이 애매. 선택지:
- **(A) 노트북에 링크 + QR 표시 → 고객이 그 자리서 QR 스캔** (부스). → **문자 발송 자체가 불필요 · 무료 · 정책 무충돌.** ← **추천**(가장 단순, "지금 QR 남김"과도 자연스럽게 연결: 다만 계약서가 이미 채워진 상태로 열림).
- **(B) 서버가 SOLAPI로 문자 자동발송** — 링크 문자 1건 전송. **⚠️ 기존 '자동발송 금지' 정책 예외 필요 + SOLAPI 건당 과금**(카톡처럼 유료). 사장님 승인 시에만.
- **(C) 노트북 [보내기] → 사장님 폰 앱에 "이 번호로 링크 보내기" 푸시 → 폰이 ▶ 발송**(기존 정책 유지, 무료). 구현 더 복잡.

> 목업엔 (B)처럼 그렸지만 **정책상 (A) 추천.** 사장님께 A/B/C 확인 후 확정.
