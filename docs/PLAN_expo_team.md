# 박람회 팀 시공 — 디지털 재구성 설계 (2026-07-21, Fable 5 논의)

> 박람회에서 여러 줄눈 팀이 부스를 만들어 상담·계약·시공하는 프로세스를 시공막내로 디지털화.
> 핵심 통찰: **"종이 계약서를 없애는 것(①)" 하나만 풀면, 나머지 통점(②분배·③일정·④현장확인)은 데이터가 이미 디지털이라 소프트웨어가 거의 공짜로 풀어준다.** → MVP는 무조건 ①.

## As-is + 4대 통점
박람회 개막 → 팀 연합 부스 → 고객 상담 → **①종이 계약서 수기 작성** → 폐막 후 **②계약서를 금액 맞춰 손으로 균등 분배**(총액÷인원) → **③각자 자기 몫 고객에 일일이 전화, 안 겹치게 일정**(하루 2~3세대 한계) → 시공 당일 **④종이 계약서 재확인**(시공범위·서비스·잔금).
- ① 입력이 종이 = 근본 원인. ② 암산 분배 = 계산 문제. ③ 희망일 모른 채 전화 = 순서 문제. ④ 종이에만 = ① 풀면 공짜로 풀림.

## To-be 프로세스 (단계 + 재활용 자산)
- **A. 박람회 세션 만들기** 🆕 — 행사·기간·팀원 명단(전화번호). 얹기: 팀 관리 화면(프로토 #s-team)+서버 team API.
- **B. 상담→QR→고객 폰 계약서** — 상담원 폰 [계약서 QR] → 고객이 찍음 → 웹 계약서(앱 불필요). 얹기: **미러 v2 QR 패턴(MirrorRepository.myCode/QrGen)** + **접수서(openQuote)**. 차이: 개별 문자발급 → "상시 QR, 찍는 사람마다 새 세션"(서버 발급 변경, 작음).
- **C. 상담원 체크 → 고객 폰 실시간 반영** — 상담원이 항목·서비스·"잔금 안내함" 체크 → 고객 폰 2~3초 폴링 반영. **웹소켓 불필요**(마주 앉아 있고 세션 몇 분, 서버=SQLite+FastAPI 폴링 일관). 필드 안 겹침(상담원=항목쓰기, 고객=확인/희망일).
- **D. 희망 시공일 3개 + 접수 완료** — 달력에서 1·2·3순위 + 동의(프로토 q-agree). 얹기: openQuoteDatePick(확정일1개 → 3개 복수선택 확장). 완료 시 계약서 스냅샷 서버 저장 + 고객에 사본(openQuoteDoc 패턴).
- **E. 폐막→자동 균등 분배 (제안→확정)** 🆕 — 팀장 [분배하기] → 금액균등 제안 → 표에서 스왑 조정 → 확정.
- **F. 확정→각 팀원 앱 자동 등록** ⭐최대 재활용 — 서버가 계약 담당자를 팀원 phone으로 박음 → 각 팀원 RING-GO의 **기존 IntakeSyncManager 폴링이 자기 몫을 그대로 수신**(고객·주소·총액·계약금·타임라인 자동). **앱 신규코드 거의 0**. 부수효과: 팀원 전원 앱 설치 필요.
- **G. 충돌없는 자동 일정 (제안→확정)** 🆕 — [담당자+희망일3+하루cap] → 겹침없는 초안 → 팀원 확정 → 고객 "○일 확정" 문자. 같은고객 2번째=JobEntity(v42)가 받침.
- **H. 팀 공유 스케줄 보드** — **미러 v2 board(여러 owner 스냅샷 합산 렌더, 색구분, 60초 갱신) 복제 = 팀 보드**. 변경알림=FCM.
- **I. 시공 당일** — 고객카드에 이미 다 있음(F에서 자동) + [계약서 보기](D 스냅샷, openQuoteDoc 스타일). 종이 재확인 소멸.

## 이미 있음 vs 새로 필요
- **앱(우리)**: QR생성(QrGen)✅ · 계약수신·고객등록(IntakeSyncManager)✅ · 고객카드/캘린더/정산필드✅ · JobEntity(v42)✅ · FCM✅ · 팀화면✅ / 🆕박람회세션화면·상담원계약서화면·[계약서보기]. (분배·일정 확인화면은 **웹으로 먼저** 추천 = 앱 릴리스 없이, 팀장만 쓰는 저빈도)
- **서버(cowork)**: intake API✅ · 미러QR/뷰어/board✅ · team API✅ / 🆕expo_contracts(체크json·희망일3·담당·상태) · 계약서세션 endpoint(2~3초 폴링) · 계약서 웹페이지 · 분배엔진·API · 스케줄엔진·API · 확정→팀원 submissions 라우팅 · 팀 보드.

## 알고리즘 (둘 다 "제안 후 사람 확정")
- **분배 = 그리디 LPT**: 금액 큰 순 정렬 → 한 장씩 "현재 합계 최소 팀원"에 배정 → 팀원별 ±편차 표시. 스왑으로 조정+실시간 재계산. 고정배정·가중치(신입 0.5인분) 옵션. **완전자동 금지**(상담자·거리·기여 등 금액 밖 변수 + 돈은 사람이 도장). 엣지: 초대형계약1장>목표(경고), 분배후취소(자동재분배X·기록만), 뒤늦은계약(미분배 배지·수동).
- **스케줄 = MRV 그리디**: 계약별 가능슬롯(희망3중 cap 남은날) 계산 → 선택지 적은 것 먼저 → 1→2→3순위 시도 → 3개 다 실패=조정필요 목록(근처 빈날 대안). cap 기본2. 확정→고객 "희망하신 ○일 확정" 문자(3개 다 안된 고객만 실제통화). 엣지: 인기날짜 쏠림(수용현황 표시), 일정변경(담당자앱 날짜만 수정→보드 자동갱신), 여러날 시공(scheduledWorkDays 연속 cap 차감).

## 단계적 구현
- **Phase 1 MVP — 종이 없애기(①④ 소멸)**: QR→고객폰 계약서(항목·금액·서비스·특이사항·동의·희망일3)→제출→상담원앱 자동등록+[계약서보기]. **실시간 체크는 빼고 단방향**(접수서 흐름 그대로). 앱 작음/서버 중간. 리스크 낮음. → 데이터 쌓이기 시작.
- **Phase 2 — 자동분배+각자앱 자동등록(② 소멸)**: 행사·팀원 등록→분배 제안(LPT)→웹서 스왑·확정→IntakeSync 수신. 앱 작음/서버 중간. 팀원 앱설치 전제(폴백=웹 목록).
- **Phase 3 — 자동일정+팀보드(③ 소멸)**: 스케줄 제안(MRV)→확정→고객 문자→미러board 복제 팀보드. 앱 작음/서버 중간~큼.
- **Phase 4 — 라이브 상담세션(비전의 실시간 체크)**: 2~3초 폴링 양방향. 앱 중간+서버 중간. **일부러 마지막**(통점 4개 중 이거 없어 안 풀리는 건 없음).
- 각 Phase 끝: SYNC append + 서버 핸드오프 md.

## 사장님이 정할 것
1. 분배 풀: 부스 전체 한 풀? **팀별로 자기 팀만**?(예시상 팀별로 읽힘) 2. 균등 기준: 금액?/건수?/가중치? 3. 확정 권한: 팀장 1인?(추천)+FCM 통지 4. 계약 취소 정산 규칙(시스템은 기록만) 5. 계약서 법적 수준: 서명(손글씨 캔버스)·계약금 확인·개인정보 동의 넣나? 6. 하루 최대 세대수 기본값(2?)·팀원별 다름? 7. 팀 구조: phone 명단=팀(추천)? 유료 팀기능(과금 지점)? 8. 계약서 템플릿: openQuote 3단계 + 박람회용 가감(프로토에 없음 → **사장님이 템플릿 확정 필요**).

## 전략 평가 (Fable)
- **곁길 아님**: 박람회 팀 = 1인 사장들이 행사때만 뭉치는 임시연합, 분배 끝나면 각자 자기 RING-GO 관리 → "협업 현장(사장↔사장)"·미러와 같은 계열, 1인 제품철학과 안 충돌.
- **큰 기회**: 분배받으려면 팀원 전원 앱 설치 → 박람회 1회에 시공인 5~10명 단체 온보딩(10만 목표에 딱, 타깃 유저가 물리적으로 모이는 몇 안 되는 장소). 재활용 이득 이례적으로 큼(계약서=접수서, QR=미러, 자동등록=IntakeSync 무수정 수준).
- **리스크**: 박람회 연 몇 회=이것만으론 리텐션 약함 → "행사 후 일상 CRM으로" 잇는 설계(Phase2 자동등록이 다리) 필수. 서버 부하 cowork 집중. 현장 통신 나쁠 때 폴백(코드 손입력, 미러v2 방식) 처음부터. 실전 박람회 투입 일정에 맞춰 Phase 진행.
- **결론**: Phase1을 "접수서 확장"으로 작게 → 실제 박람회 1회 투입 후 Phase2~3 결정. 박람회 기능은 "박람회 모드"로 격리해 1인 코어 UX 불변.
