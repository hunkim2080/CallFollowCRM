## 4. 미수(못 받은 돈) 계산 규칙 — 제가 정한 로직
- **받을 돈(total)** = 총액. 총액 없으면 (계약금 + 잔금).
- **잔금 금액** 안 적었으면 = (총액 − 계약금) 으로 자동 추정. (사장님이 직접 적었으면 그게 우선)
- **받은 돈** = 받음 체크된 계약금/잔금 합.
- **완납** = 받은 돈이 받을 돈 이상.
- 돈 정보가 하나도 없는 고객은 정산 목록에서 **제외**.
- **이유:** CustomerEntity의 기존 주석("balance = total − deposit")과 일치시킴. 7가지 경우를 테스트로 박아둠.

## 5. 완납 오탭 방지 방식
- 잔금 "받음" 켤 때 → **"전액 받았어요?" 확인 한 번** 띄움. (실수로 완납되는 것 방지)
- 완납된 카드엔 **"완납 취소"** 글자 → 되돌리기.
- **이유:** 예전에 사장님이 "버튼 잘못 눌러 전액완납됐다"고 하신 통점 반영.

## 6. 토글 시 자동 카테고리 갱신 유지
- 정산에서 계약금/잔금 받음 바꾸면, 고객상세와 똑같이 **자동 분류(reclassify)** 도 호출.
- **이유:** 같은 데이터를 두 화면(정산/고객상세)에서 만지니 동작을 일치시켜 혼란 방지.

## 7. 작은 것들
- 금액 표시 = `1,200,000원` 형식(천 단위 콤마) — `MoneyFormatter` 새로 만듦.
- 미수 0원이면 빨강 대신 **"못 받은 돈 없어요 👍"** 긍정 문구(매출 불안 완화 톤).

# 정산 Phase 2 (현금흐름) — 사장님 "2 가자" 지시로 진행 + 제가 정한 세부

사장님이 Phase 2 진행을 지시 → 아래는 제가 판단한 부분:

## 8. DB는 "새 테이블 추가"로만 (가장 안전한 마이그레이션)
- `manual_cash` 테이블 신규 추가(v19→v20). **기존 데이터/테이블은 안 건드림** = 깨질 위험 최소.
- 안전망: 혹시 마이그레이션 실패해도 `fallbackToDestructiveMigration`이 켜져 있어 앱이 안 죽음(최악의 경우 캐시성 데이터만 리셋).
- ⚠️ 그래도 **폰 첫 실행 때 실제로 마이그레이션이 돌아요** → 아침에 정산 들어가보시고 이상 없는지 확인 필요.

## 9. 현금흐름 = 정산 화면 안 "탭"으로 (별도 화면 X)
- 정산 화면 위에 **[미수금] [현금흐름]** 탭 두 개. 하나의 정산 안에서 전환.
- 이유: 프로토도 정산 안에 같이 있었고, 화면을 또 만들면 길 찾기 복잡.

## 10. 현금흐름에 자동으로 들어오는 돈 (제가 정한 규칙)
- **들어온 돈(확정)** = 계약금/잔금 받은 날에 자동 표시.
- **들어올 돈(예정)** = 아직 못 받은 미수 + 시공 예약일 있으면 그 날에 표시.
- **직접 기록** = 사장님이 손으로 적는 현금(자재비 등). 수입/지출·완료/예정 선택.
- 4색: 들어온(진파랑)/들어올(연파랑)/나간(빨강)/나갈(연빨강) — 프로토 색 그대로.

## 11. 순이익 두 가지로 표시
- **확정 순이익(실현)** = 실제로 오간 돈만. **예상 순이익(추정)** = 예정까지 포함.
- 월매출 전월대비는 Phase 3로 미룸(일당 자동차감과 함께).
