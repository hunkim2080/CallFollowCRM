# TimeTree 벤치마킹 → 시공막내 공유 캘린더 (2026-07-22, Fable 5 분석)

> 시공인 거의 전부가 TimeTree를 쓰는 이유 = **"공유가 편해서"**. 이걸 완벽 벤치마킹.
> **핵심 결론: 우리는 이미 70% 와 있다.** 본폰 미러(v2)가 사실상 TimeTree식 공유 캘린더(읽기전용)이고, 초대는 오히려 우리가 더 쉽다(상대 가입 불필요=웹). 빠진 건 **"상대가 일정을 넣기"(쓰기) 하나**.

## "공유가 편하다"의 실체 = 4가지 (TimeTree 분해)
1. **캘린더 단위 공유** — 초대 1번이면 이후 넣는 모든 일정이 자동 공유. (일정마다 공유 X) ← 최대 핵심
2. **초대 = 링크 하나** — 만들고 링크 보내면 끝.
3. **대칭 쓰기** — 들어온 사람 누구나 일정 추가/수정.
4. **색 + 필터** — 누구 일정인지 색으로, 필터로 섞어/따로 보기.
- TimeTree 숨은 마찰: **받는 사람도 앱 설치+가입 필요.** 우리 미러는 웹이라 무가입 → 우리가 이김.

## 우리 현황 대비 (이미 충족 3 / 결핍 1)
- ①1회 초대 자동공유 → **미러 스냅샷 push로 충족**
- ②QR/링크 무가입 입장 → **충족 + TimeTree보다 나음**
- ④색 구분 → **충족**(tint, 최근 "협업 색 구분")
- ③**상대가 일정 넣기(쓰기) → 유일한 결핍 = MVP**

| TimeTree | 판정 | 이유 |
|---|---|---|
| ④ 공유 캘린더 | **변형 흡수 · 최우선** | 미러 v2 승격 + 쓰기 1방향 |
| ⑥ 컬러 월뷰 | 이미 있음 | ScheduleScreen jbar lane·월 스와이프·협업 마커 |

## 왜 시공인이 쓰나 + 우리 wedge
- 진짜 이유: 1인 사장도 실제론 임시 팀(**사모님**=예약 대신 잡음 · 일당사장 · 협업사장). "누가 어느 현장, 빈 날 언제"를 전화 없이. 특히 **부부 공유(사모님이 예약을 직접 넣음)**가 핵심 — 미러가 겨냥한 자리인데 **읽기전용이라 반쪽**.
- **우리 wedge**: TimeTree 일정 = 그냥 글자. 우리 일정 = **고객 카드**(탭→전화·대화·정산·지도). 잔금·미수금이 달력에 붙음. 공유해도 고객번호 가려짐.
- 킬러: **"타임트리는 달력을 공유하고, 시공막내는 사업을 공유합니다 — 고객 번호는 지키면서."**

## 공유 캘린더 설계 (새 기능 X, 미러 승격 + 쓰기 뚫기)
- **달력 단위 = 사업장(owner_phone)** (board 합산 이미 구현).
- **초대 = 미러 QR 그대로**(자동수락+손입력코드).
- **읽기 = 스냅샷 push 유지**(60초 폴링, 웹소켓 불필요).
- **쓰기(신규) = "제안 → 사장님 확인" 게이트**: 뷰어에 [+ 일정 추가] 폼 → 서버 `mirror_inbox` → 앱 폴링(IntakeSyncManager 패턴 복제) → 알림 "사모님이 일정 넣음 [확인]" → 확인 시 고객+scheduledWorkDate 생성. (대칭 쓰기 X = 충돌·권한 지옥 회피 + CRM 오염 방지 + 1인 사장 최종결정 원칙)
- 앱(우리): 미러를 "달력 공유"로 승격·진입점·inbox 확인 시트·온보딩 팁·day카드 진입점 (소). 서버(cowork): mirror_inbox 테이블+뷰어 폼+GET/ack+고지 페이지+보존정책 (중).

## 개인정보/신뢰 3단 층위 (★이미 코드에 구현 — 명문화만)
| 층위 | 상대 | 보이는 것 | 근거 |
|---|---|---|---|
| 1 | 본폰·사모님(같은 사업장) | 전부 + 금액 감추기 기본 | 미러 스냅샷 + "금액 감추기(기본)" |
| 2 | 팀원(직원) | 이름·날짜·시간·주소·**팀 메모만** | pushSnapshotFor "직원 메모=사장님이 적은 것, 고객메모 아님" |
| 3 | 협업 사장 | **안전 라벨만**(번호·대화 절대 X) | collabTitleOf "번호/대화 절대 미포함" |
- TimeTree 약관서 가져올 것: 공유 켜기 시 **고지 시트**(이 사람에게 보이는 것) + 동의 + 나가면 접근상실 + 스냅샷 삭제. 처리방침(si0in.kr/privacy)에 "달력 공유 범위" 조항 추가. **협업사장엔 최소화 = 지금 코드 원칙 절대 유지**.

## 단계
- **Phase 0 (앱 소, ~1세션)**: 미러 v2 → "달력 공유(사모님·본폰)"로 승격, 일정 탭 진입점 + 온보딩 팁 + 고지 시트. 코드 거의 안 짜고 **포지셔닝만으로 "TimeTree처럼 공유되네"**. QR 실사용 검증 마무리.
- **Phase 1 (서버 중심, MVP)**: 사모님 쓰기(뷰어 폼→inbox→앱 확인). = 공유 최소핵심 4개 전부 충족.
- **Phase 2**: 박람회 팀보드(PLAN_expo_team Phase 3 그대로) = 팀 상시공유 실험장.
- **Phase 3**: day카드 사진/계약서 진입점, 필터칩(프로토 갱신 후), 시간순 정렬.

## 솔직한 평가
- TimeTree 통째 복제는 함정 — 시공인에게 실제 통하는 건 ④공유(+⑥밀도·⑤색)뿐. ②핀·③타임라인은 종일단위 시공과 안 맞음. 자원을 ④에 집중.
- 우리는 이미 7부 능선. 남은 건 쓰기 1방향, 그것도 IntakeSync 패턴 복제로 작게.
- 리스크: 대칭쓰기 지옥(→제안-확인), 캘린더 UI를 TimeTree처럼 바꾸고싶음(→프로토 §0 위반, 갱신+확정 후만), 서버가 cowork에 몰림(→핸드오프 필수).
