# ANDROID HANDOFF — Play Console 「데이터 보안」 양식 ↔ 실제 수집 대조 감사

작성: cowork(맥미니) · 2026-07-08 · 사장님 지시
목적: 데이터 보안 양식 응답과 앱의 실제 수집·전송이 어긋나면 **출시 후 앱 정지 1순위 사유**.
프로덕션 심사 통과 전후 어느 쪽이든, 아래 대조표를 실제 코드·매니페스트 기준으로 검증해 줄 것.

## 1. 서버가 아는 "실제 수집·전송" 목록 (개인정보 처리방침 v3 = /privacy 기준)

| # | 항목 | 수집 경로 | 서버 저장 | 국외 전송 | Data safety 카테고리(예상) |
|---|---|---|---|---|---|
| 1 | 휴대전화 번호 | 가입 인증(SMS)·접수서·협업 | ✅ (탈퇴 시 파기) | ❌ | 개인 정보 > 전화번호 |
| 2 | 문자 메시지 본문 | AI 기능 사용 시 전송 | ❌ 원본 미저장 (요약만) | ✅ Anthropic·Google (미국) | 메시지 > SMS |
| 3 | 통화 녹음 → 텍스트 | AI 요약 사용 시 | ❌ 원본 미저장 | ✅ 상동 | 오디오 (녹음이 기기 내면 '수집' 정의 확인 ⭐) |

| 6 | (선택) 보낸 문자 원문 — 톤 학습 | optional_quality 동의 시 | ✅ 2년 | ❌ | 메시지 > SMS |
| 7 | (선택) 상호·업종·활동지역 | 프로필 입력 | ✅ | ❌ | 개인 정보 |

## 2. android 가 검증할 것
1. **매니페스트 민감 권한 전수** (READ_SMS/RECEIVE_SMS/READ_CALL_LOG/RECORD_AUDIO/READ_CONTACTS 등)
   ↔ 양식의 수집 항목 응답 ↔ 권한 선언 양식(Permissions Declaration) 3자 일치 여부.
2. 위 표에 없는데 앱이 실제로 모으는 항목이 있으면 (예: 연락처 이름, 사진, 위치) → **표에 추가 보고**.
   반대로 양식에 "수집함"인데 실제 안 모으는 항목도 보고 (과다 신고도 심사 리스크).
3. 공통 응답 확인: 전송 중 암호화 = 예(TLS) / 삭제 요청 수단 = 예(탈퇴+앱 내 삭제) /
   제3자 공유 = SOLAPI(문자 발송·국내), Anthropic·Google(AI 처리·미국) — "공유" 정의상 데이터 처리자(processor)로
   처리되는지 양식 문구 기준으로 판단 ⭐.
4. ⭐ 표시 2건은 판단 애매하면 지어내지 말고 SYNC 에 의문 블록 + 사장님 보고 (CLAUDE.md §8).

## 4. 감사 결과 (android · 2026-07-08)

실제 검증 기준: `AndroidManifest.xml` 권한 전수 + 각 권한 실제 사용처(코드) + 서버 전송 payload(각 Repository) + `docs/PLAY_DATA_SAFETY_ANSWERS.md`.

### 4.1 민감 권한 ↔ 실제 수집 ↔ 양식 (3자 대조)

| 매니페스트 권한 | 실제 용도(코드) | 서버 전송? | Data safety 카테고리 | 양식 일치 |
|---|---|---|---|---|
| READ_SMS·RECEIVE_SMS·WRITE_SMS·RECEIVE_MMS·RECEIVE_WAP_PUSH·SEND_SMS | 문자/사진 수발신(기본 SMS 핸들러), AI 답변·다듬기에 본문 전송 | ✅ 본문 전송(/api/refine·suggestions) | 메시지>SMS/MMS + 기타 인앱 메시지 | ✅ 일치 |
| READ_CALL_LOG | 전화 올 때 상대 정보 카드(발신번호 표시) | 번호만(전화번호로) | 개인>전화번호 | ✅ (단 권한선언에 "발신번호 표시·스팸" use-case 必 — 사장님 콘솔 대기) |
| READ_PHONE_STATE | 통화 상태 감지(카드 트리거) | ❌ | (수집 아님) | ✅ |
| READ_MEDIA_AUDIO | **기존** 통화녹음 파일 읽어 업로드(에이닷 등이 만든 파일) | ✅ 파일 업로드(통화요약) | 오디오>음성/사운드 녹음 | ✅ |
| SYSTEM_ALERT_WINDOW | 통화 前 상대정보 오버레이 | ❌ | (수집 아님) | ✅ |
| ACCESS_FINE/COARSE_LOCATION | **지오펜스만**(현장 주소→좌표→3km 반경 자동도착). 기기 GPS 좌표는 앱이 읽지도·보내지도 않음 | ❌ 좌표 미전송 | (위치 수집 아님) | ⭐ 아래 |
| READ_EXTERNAL_STORAGE(max32) | 구형 기기 사진 접근(현재는 PickVisualMedia 선택기) | 사진은 업로드됨 | 사진 및 동영상>사진 | ✅ |
| INTERNET·NETWORK·WIFI·WAKE_LOCK·VIBRATE·POST_NOTIFICATIONS | 통신/알림/시스템 | ❌ | (수집 아님) | ✅ |

### 4.2 없어서 다행인 것 (핸드오프 §2가 걱정한 항목)
- **RECORD_AUDIO 선언 안 함.** 앱은 **녹음을 하지 않음** — (a) 음성입력은 시스템 STT(텍스트만 반환), (b) 통화녹음은 **다른 앱이 만든 파일을 읽어 업로드**만 함. → "직접 녹음" 아님(권한선언·양식에서 이 구분 유지).
- **READ_CONTACTS 선언 안 함.** 팀/수첩의 "연락처에서 불러오기"는 **시스템 선택기(ACTION_PICK)** — 사용자가 고른 **1건만**(이름+번호) 접근. 연락처 전체를 읽지 않음.
- **READ_MEDIA_IMAGES 선언 안 함.** 사진은 시스템 Photo Picker(권한 없음).

### 4.3 ⭐ 판단 필요 (지어내지 않고 보고 — CLAUDE.md §8)
1. **위치(FINE/COARSE)** — 양식 "위치 수집 안 함"은 **기술적으로 맞음**(좌표 미전송·지오펜스 온디바이스). 단 Google 이 FINE_LOCATION 을 엄격히 봄 → **권한 선언(Permissions Declaration)에 "지오펜스=협업 현장 자동 도착 감지" use-case 를 명시**하는 게 안전. (양식 자체는 그대로 OK)
2. **연락처(Contacts) 카테고리** — 선택기로 고른 1건의 이름+번호가 서버로 감(팀 초대). 이미 "전화번호/이름" 카테고리로 커버 → **"Contacts" 별도 신고 불필요**(선택기 방식=파일피커와 동일 논리). defensible.
3. **제3자 공유 정의** — SOLAPI(국내 문자발송)·Anthropic/Google(AI, 미국)은 **처리자(processor)** → "공유=아니오" 맞음. 단 문자본문이 **Anthropic(미국)로 국외전송**되는 건 처리방침 v3 §5-2 에 이미 명시. 양식은 "공유=아니오"이되 국외전송 사실은 방침과 세트로 유지.

### 4.4 cowork 확인 필요
- **삭제 요청 경로**: 양식 "데이터 삭제 요청 가능=예" 를 선택하려면 `si0in.kr/privacy` 에 삭제 방법(이메일 등)이 명시돼 있어야 함. 있으면 "예", 없으면 방침에 한 줄 추가.

### 4.5 결론
- **명백한 불일치(허위신고) 없음.** 양식(PLAY_DATA_SAFETY_ANSWERS.md)은 실제 수집과 일치.
- 조치: (a) 권한선언에 위치=지오펜스 use-case 추가 권장, (b) 삭제경로 방침 문구 확인. 둘 다 **심사 통과 후** 반영(심사 중 수정=대기열 리셋).
