# ANDROID 핸드오프 — 유료전환 D-14 사전 동의 화면

작성: cowork · 2026-07-10 · **갱신 2026-07-11 (법률 크로스체크 Q9·Q10·Q11 반영, 추가118)**
서버 배선 필요 없음(서버 완료). 앱 UI만 이 문서대로 맞추면 됨.

## 왜
전상법 §13조의2 + 시행령 §20조의2 + 약관 §8: 무료 체험이 유료로 자동 전환되기 전 **최소 14일 전에** 대금·결제주기·해지조건을 고지하고 **동의**를 받아야 함. 동의 없으면 결제 연동 후에도 자동결제 금지.

## 서버가 주는 것
- `GET /api/conversion/status?phone=` →
  `{ freeUntilMs, daysLeft, noticeDue, consented, consentedPlan, consentDocVersion, cancelNotice, plans[] }`
  - `noticeDue=true` → D-14 안내+동의 화면 노출. `consented=true` → 재노출 안 함(설정에서 변경만).
  - **`plans[]`** = 요금제별 법정 고지 문안(서버 원본). 모달은 이 문자열을 **그대로** 표시할 것(앱에서 금액·문구 하드코딩 금지). 각 항목:
    ```
    plan, planLabel,
    beforeText  = "현재 무료 체험 (0원)"                     ← 변동 전 대금
    afterText   = "2026년 9월 9일부터 월 55,000원(부가세 포함)"  ← 변동 후 대금(부가세 포함 총액)
    totalKrwVatIncluded (55000/110000), supplyKrw, cycle="월 1회 정기결제", startAtMs,
    cancel            ← 해지 조건·방법·효과(환불 기준 포함)
    priceIncreaseNote ← 인상 시 30일 전 별도 동의
    ```
- `POST /api/conversion/consent` `{ phone, plan:"standard_50k"|"premium_100k", agreed:true|false }`
  → `{ ok, snapshotSha256 }`. 서버가 **동의 당시 고지 문안 스냅샷+해시+기기정보**를 저장(5년 보존). 앱은 별도 증빙 저장 불필요.

## 앱이 할 것 (모달)
1. 홈 진입 시 `conversion/status` 폴링 → `noticeDue && !consented` 면 모달.
2. **모달 필수 고지(Q9 — 빠지면 시정조치/과태료, 기존 동의 무효화 위험):**
   - **변동 전후 대금 대비**: `beforeText` → `afterText` 를 한 화면에 나란히 (예: "무료 체험 0원 → 9/9부터 월 55,000원").
   - **총액(부가세 포함)** 첫 화면부터: "월 5만원(부가세 별도)" 금지 → **"월 55,000원(부가세 포함)"**. (개정 전상법 다크패턴 '순차공개 가격' 저촉)
   - **결제 주기**: `cycle`.
   - **해지의 조건·방법·효과**: `cancel` 전문 표시(방법만 X, 환불 기준까지).
3. **청약 확인 단계(Q10)**: 요금제 선택 → 결제수단 등록 **직전**에 전상법 §14 청약 확인 화면 1단계(구독 내용·금액·결제일 최종 확인 + 정정 기회) 삽입.
4. [동의하고 계속] → `consent {plan, agreed:true}` / [지금은 안 할게요] → `{agreed:false}` (또는 닫기).
5. **결제 완료 알림(Q10)**: 실제 결제 붙은 뒤, 매 결제 시 문자/푸시 완료 알림. (카드사 사전 알림은 토스·카드사 영역 = 회사 의무 아님)

## 402 게이팅 시 반드시 지킬 것 (Q11 — 데이터 인질화 방지)
미동의로 무료 만료되어 유료 기능을 잠그더라도:
- **기존에 저장한 데이터(고객 정보·견적·일정) 열람과 내보내기(다운로드)는 종료일부터 최소 30일 열어둘 것.** 이 기간 서버는 해당 데이터를 삭제하지 않음.
- 잠그는 것은 **신규 기능 사용**만(접수서 발행, AI 기능 등) — 구독 재개 시 해제.
- 이유: 자기 고객 정보 접근까지 막으면 약관규제법 §6(신의성실) 소지 + 사장님이 고객의 삭제요청 대응 등 개인정보 의무를 못 지키는 2차 문제.

## 주의
- 실제 결제(토스)는 별도(체크리스트 C). 이 화면은 "동의 수집"까지.
- 금액·문구는 서버 `plans[]` 기준(하드코딩 금지). plan 값 = standard_50k / premium_100k 고정.
- 요금 **인상** 시엔 별도로 인상 30일 전 사전 동의 필요(`priceIncreaseNote`) — 결제 로직에 미리 반영.
