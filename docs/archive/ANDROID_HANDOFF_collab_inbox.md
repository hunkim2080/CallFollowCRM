## 요청 사항 — 협업 inbox UI

### 1. "공유받은 현장" 탭 상단 알림 배너

`commit 6d04a20` 에서 "공유받은 현장" / "내가 공유한 현장" 으로 분리하셨죠. "공유받은 현장" 탭 **맨 위** 에:

```
┌────────────────────────────────────┐
│ ⚠️  응답 안 한 협업 요청  3건       │
│     수락 / 거절 선택해주세요  →    │
└────────────────────────────────────┘
```

- pending 카운트 > 0 일 때만 노출.
- 클릭 시 pending 카드들로 스크롤 (또는 별도 inbox 화면).

### 2. pending 카드 별도 섹션

탭 안에서 **3단 분리**:
1. **⚠️ 응답 필요 (pending)** — 맨 위, 강조 색 (노랑/주황 보더 또는 좌측 띠).
2. **🟢 진행 중 (accepted, progress != completed)** — 그 다음.
3. **✓ 완료 / 종료** — 접힘.

각 pending 카드에:
- **[수락]** [거절] 버튼 — 카드 안에 박아 누르기 쉽게 (별도 화면 진입 X)
- "🤝 디테일라인 사장님이 6/17 줄눈 현장에 같이 가시자고 해요" 같은 문구
- "X일 전 도착" 표시 (오래 안 응답하면 시급도 보임)

### 3. API 변경 없음

`/api/shared/with-me` 가 이미 status + scheduled_at_ms + owner_name (raw) + title + daily_wage 다 돌려줍니다.

응답 예 (확인):
```json
{
  "sites": [
    {
      "share_id": "sh_XXX",
      "owner_phone": "01080052080",
      "owner_name": "디테일라인",
      "title": "동탄 줄눈",
      "scheduled_at_ms": 1750000000000,
      "time_label": "오전 9시",
      "daily_wage": 25,
      "status": "pending",            ← 이걸로 inbox 그룹화
      "progress": "assigned",
      "created_at_ms": 1749900000000
    }, ...
  ]
}
```

앱이 status 별로 정렬 + 그룹화만 하면 됨. 서버 변경 X.

### 4. 푸시 본문 (선택)

지금 invite FCM 본문 = `🤝 디테일라인 사장님이 함께 일하자고 해요` 정도. 그치만 **푸시 놓쳐도 inbox 가 보호망**이니까 푸시 자체는 그대로 둬도 OK.

### 5. 베타 사용자 즉시 효과

이번 17·24일 사건의 옛 pending share 도 자동으로 inbox 에 보임 (서버는 이미 pending 다 돌려주니까). B 사장님이 앱 켜면 그날 요청들이 보임 → 수락/거절 가능.
