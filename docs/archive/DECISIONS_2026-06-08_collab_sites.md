# DECISIONS — 협업 현장 야간 자율 구현 (2026-06-08)

사장님 지시: "협업 현장 디테일하게 구현. 선택할 게 있으면 **추천안으로 모두** 진행. 다음날 확인."
→ 아래는 그 추천 판단들 + 무엇을 만들었고 무엇을 서버 후로 미뤘는지. (룰: 위험건은 보류+추천)

## 핵심 방침
에이닷 음성요약 때처럼 **서버 우선(server-first)** 으로 갔습니다.
협업 현장은 기능의 ~70%가 서버 신규 endpoint(초대/수락/with-me/완료알림)에 의존 →
**오늘 = 앱 단독으로 완결되는 것 + 서버 붙으면 바로 켜질 최종 UI** 까지 만들고,
서버 의존 강한 부분(A측 공유 버튼·캘린더 보라점·A측 입금카드)은 **명세(핸드오프)로 넘김**.
이유: 서버 없는 큰 UI를 추측으로 미리 짜면 깨지거나 버려질 위험 → 사장님이 아침에 "안 돼요"를 겪지 않게.

## 오늘 구현한 것 (빌드·설치 완료)
1. **입금 계좌 등록** — 더보기 → 견적서·사업자 정보에 **은행 / 계좌번호 / 예금주** 추가. AppPreferences 저장. (앱 단독, 완전 동작)
2. **협업 현장 화면 (B = 협업자)** — 더보기 → "협업 현장" 진입. 프로토 `collab-sites-proto.html` 의 b-list/b-detail 1:1:
   - 목록: 보라 🤝 카드 + 날짜칩 + "내 고객과 따로 모여요" 안내. 비었으면 "공유받은 현장 없음" 안내(서버 대기).
   - 상세: 협업 pill + 주인 이름, 날짜·시공, 주소+길찾기, 대표님 전달사항, **진행 stepper(배정/출발/도착/완료) + 다음단계 버튼**, "🔒 이 현장만 보여요" 벽 안내.
   - 완료 누르면 입금 계좌를 같이 전송(서버 progress payload). 계좌 미등록이면 등록 유도 문구.
3. **SharedSiteRepository** — 서버 협업 API 클라이언트(with-me/invite/respond/progress/paid/owner-exists). 서버 명세 = `SERVER_HANDOFF_collab_sites.md`.

## 추천으로 정한 선택들 (사장님 확인용)
| # | 선택지 | 정한 것(추천) | 이유 |
|---|---|---|---|
| 1 | 완료 알림에 금액 포함? | **계좌번호만**(금액 X) | 사장님 6/8 결정. 금액은 둘이 따로 합의. |
| 2 | 계좌 등록 위치 | **사업자 정보 안** | 이미 있는 화면 재사용, 견적서에도 활용. |
| 3 | 입금완료 확인 | **A 체크 → B 알림** | 서로 깔끔·다툼 방지. (서버 paid endpoint) |
| 4 | 협업 화면 메뉴 위치 | **더보기 → "함께 일하는 사람"** (팀 관리 아래) | 팀과 한 묶음, 비즈니스 tier. |
| 5 | 요금제 | **비즈니스 tier** | 팀 관리와 동일(프로토/스펙). |
| 6 | 빈 목록일 때 | **친절한 빈 화면** | 서버 전이라도 안 깨지고 의도 전달. |
| 7 | 길찾기 | **기기 지도앱(geo:)** | 별도 연동 없이 즉시. |
| 8 | 예금주 비었을 때 | **대표자 이름 자동 사용** | 입력 부담↓. |
| 9 | 진행 단계 어휘 | departed/arrived/completed (**팀 events 재사용**) | 서버 재사용 80%. |

## 서버 후 이어서 할 앱 작업 (보류 — 추천과 함께 핸드오프에 기재)
- **A측 "협업 현장으로 공유" 버튼 + 공유 시트** (고객카드, 프로토 a-card/a-share). 상대 번호 입력 → invite. *(고객카드는 민감 화면이라 서버 계약 확정 후 한 번에.)*
- **A측 "협업 중" 카드** — 상대 진행/사진/완료+계좌 수신 + **입금완료 버튼**(프로토 a-after, §10). site-photos/notes 재사용.
- **캘린더 보라점** — 일정에 협업 현장 보라색 점(프로토 b-cal). with-me 데이터 안정화 후.
- 위 3개는 모두 서버 endpoint(§invite/with-me/progress/paid) 가 있어야 동작 → 서버 회신 후 즉시 작업.
